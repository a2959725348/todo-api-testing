# 测试用例设计文档（手工测试）

> 这份文档是「功能测试」的书面产出，配合 `README.md` 里的环境和步骤一起放在 GitHub 上。
> 目标不是写得花哨，而是让人一眼看出：**你会拆功能、会设计用例、能写清楚什么情况该有什么结果。**

## 一、被测系统概述

一个仅用于练习的「待办清单」Web 服务，包含登录注册与待办的增删改查。数据存在内存里，重启即清空。

| 项目 | 说明 |
| --- | --- |
| 服务地址 | `http://127.0.0.1:5000` |
| 接口前缀 | `/api` |
| 鉴权方式 | 登录后拿 token，请求头带 `Authorization: Bearer <token>` |
| 数据存储 | 内存，重启后清空 |

## 二、功能模块划分

| 模块 | 涉及接口 | 核心功能 |
| --- | --- | --- |
| 用户模块 | `/api/register`、`/api/login` | 注册、登录、鉴权 |
| 待办模块 | `/api/todos`、`/api/todos/{id}` | 增、删、改、查、状态切换 |
| 页面模块 | `/` | 登录注册界面、列表展示与操作 |

## 三、用例设计方法

不是拍脑袋想用例，而是每个模块都套用固定的几种方法，保证覆盖面：

| 方法 | 用在哪里 | 举例 |
| --- | --- | --- |
| 等价类划分 | 用户名、密码、标题的取值 | 合法值 / 非法值 / 空值 三类各取代表 |
| 边界值分析 | 所有有长度限制的字段 | 用户名 2 / 3 / 20 / 21 位各测一遍 |
| 判定表 | 鉴权组合 | 有 token / 无 token / token 伪造 / token 属于别人 |
| 场景法 | 主流程串联 | 注册 → 登录 → 建待办 → 标记完成 → 删除 |
| 错误推测 | 异常输入 | 传 null、传数字类型、传特殊字符、带 emoji |

## 八、已知限制

- 被测服务为内存存储，重启后数据清空，因此不适合做数据持久化相关测试；
- 未覆盖性能、兼容性、安全渗透等非功能测试，不在本项目范围内；
- 前端未做响应式适配验证，仅在 1280×900 分辨率下执行。
